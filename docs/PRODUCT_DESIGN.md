# PLAYDOT 产品审查与设计规范

M1 · 2026-10-15 · 基线 `efcf5d2`。每轮只推进一个可独立回滚的交付；后续里程碑不是本轮全部实现的承诺。

## 当前事实与优先级

当前为无构建、无框架的静态站点。根 `index.html` 同时提供大厅和三个 dialog 游戏；`games/dual-axis-dodge/` 保留完整旧游戏。纯规则在大厅脚本前半段，DOM、定时器和 localStorage 在后半段。沿用这一规模，不新增框架或通用游戏引擎。

| 游戏 | 已有价值 | 当前限制 / 可复用部分 |
| --- | --- | --- |
| 反应力测试 | 随机等待、抢跑反馈、多轮中位数 | 主要考反应；复用模式切换、状态提示和计时清理 |
| 精准点击 | 大小目标与准确率，两档难度 | 同属手速，轻松模式仍限时；不当作本轮重写对象 |
| 记忆翻牌 | 图案双重辨识、不限时、成对生成 | 主要考位置记忆；与顺序记忆有明确差异 |
| 双轴闪避 | 双手独立、完整镜像、分段碰撞、完整回归 | 横屏进阶门槛高；保留独立入口和专用视觉 |

最高优先级：首页宣传区桌面至少 375px，窄屏还有单独装饰区，推迟发现游戏；深色大横幅偏竞技，与轻松入口不一致。M1 压缩首屏、使用奶油白与珊瑚色、统一基础触控与焦点规范。M4 再处理分类、最近游玩、双轴记录展示及旧游戏结束界面，不一次重写全部组件。

存储：大厅沿用 `playdot:v1:` 前缀和 `游戏:模式` 键；新游戏仅追加 `sequence:easy/challenge`，不迁移旧成绩。双轴原有键全部保留。存储失败时仍可游玩。

离线：根 `sw.js` 预缓存大厅、manifest/icon 和嵌套双轴资源；导航网络优先，大厅与双轴分别回退。大厅内新增游戏无额外资源；行为变化升级缓存版本。根页面缺少 manifest 链接，M1 补齐。

部署与测试：main 的 Pages 自动构建已成功；两项仓库 workflow 分别执行回归与日志检查。基线 main 无保护，分支 rules API 返回空数组，连接权限包含 push/admin；提交前仍检查最新 head，绝不覆盖并行更新。CI 不代表真机验收。

## 参考研究与采用判断

以下是官方页面的内容/结构研究，不是已完成真实设备视觉或交互验收。

| 官方参考 | 可确认的结构 | PLAYDOT 的选择 |
| --- | --- | --- |
| [Poki](https://poki.com/) | 分类、热门游戏和大量直接入口，强调即点即玩 | 游戏列表提到首屏附近；仅五款时保留两组有效分类，不铺空分类 |
| [Human Benchmark](https://humanbenchmark.com/) / [Sequence](https://humanbenchmark.com/tests/sequence) | 用短句说明任务；逐渐加长按键序列，出错结束 | 一句规则、明确观察/作答阶段；轻松模式增加重看机会，不采用排名或能力诊断 |
| [Neal.fun](https://neal.fun/) | 独立命名的互动项目，例如画圆、密码游戏 | 卡片表现核心动作，每款有独特符号，避免只有配色不同的重复游戏 |

研究结论是本项目的设计判断，不能据此声称已验证儿童易用性。

## 彩色轻街机规范

| 项目 | 规范 |
| --- | --- |
| 基础颜色 | 背景 `#FAF9F6`，文字 `#202124`，辅助文字 `#59616D`，边框 `#E7E4DF` |
| 品牌与辅助色 | 珊瑚 `#FF725E`、薄荷 `#73D9B3`、天空 `#80C7F7`、紫 `#B9A3F5`；浅底配深字，珊瑚按钮配深字 |
| 字体 | 原生 system-ui；正文至少 14px，卡片标题 18–20px，小字仅用于辅助信息 |
| 形状 | 卡片 20px、按钮 12px、游戏色块 18px；避免新建大量相近尺寸 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px；窄屏页边至少 13px |
| 点击 | 控件至少 44px；核心游戏块至少 64px；原生 button 支持键盘，保留缩放与页面滚动 |
| 反馈 | 按压约 120ms；正确显示文字/进度，错误显示文字与边框；不用颜色作为唯一信号 |
| 动效 | 少量位移，无频繁全屏闪烁；reduced-motion 关闭过渡、动画和位移，游戏信号仍保留必要显隐 |
| 焦点 | 高对比焦点环，dialog 有标题，状态使用 role=status；不隐去键盘焦点 |
| 布局 | 手机优先，390px 两列卡片，极窄屏一列；横屏允许 dialog 滚动，不强迫全站横屏 |

## 可验证的扩展路线

| 里程碑 | 最小交付 | 验收边界 |
| --- | --- | --- |
| M1 | 本文、紧凑明亮首页、基础触控/动效规范、manifest | 旧回归通过，双轴文件不变，独立提交 |
| M2 | 节奏记忆四块序列、两档、重开、可选声音、本机最佳、大厅入口 | 长度从 1 开始每轮 +1；轻松可重看且错后重试、挑战错后结束；正确轮数才计分；定时器/后台/重开取消旧回调；自动回归 |
| M3 | 找出不同 | 轻松不限时，形状为主要辨识通道；难度有下限，生成器批量公平性测试 |
| M4 | 分类、最近游玩、记录、导航 | 避免空分类，读取旧键不迁移，游戏入口与手机布局统一验收 |
| M5a / M5b | 一笔连线 / 节奏点击分开交付 | 连线图有解且可撤销；节奏视觉可玩、宽容判定，不以音频播放回调算玩家时差 |
| M6a / M6b | 颜色分类 / 迷你迷宫分别评估 | 默认不限时，颜色辅以形状/标记；确保有解，不堆重复内容 |
| M7 | 全站验收 | 各入口、模式、离线、成绩、横竖屏、Android/iOS 真机；记录无法验证项 |

M2 技术范围：继续使用现有 dialog、`MODES`、配置表、受管定时器与 `roundId` 会话令牌。只增加节奏规则和界面函数，不提取全部旧游戏。色块同时有固定位置、数字、图形；播放期间禁用输入。背景/返回/换模式清理所有回调与声音；显式继续后从整段重播，不能自动跳过未看见的信号。双击同一块去抖不妨碍有意重复，连点公平性加入测试。

## 真机验收待办

- Android Chrome / vivo 浏览器：窄屏首屏、双击/长按、横屏滚动、返回与后台恢复。
- iOS Safari：dialog、静音/解锁失败、低电量/后台播放中断、添加主屏幕及旧 SW 升级。
- 双轴：横屏双指、跨中线、完整镜像与碰撞手感；自动化通过也不能勾选这一项。
- 色觉差异与减少动态设置，触控误差和轻松模式难度需真人反馈。

本环境未提供 Sites 要求的 control-browser，不能执行受支持的浏览器预览/截图。Node VM 自动化验证运行逻辑与离线请求，不代替视觉或真机检查。
